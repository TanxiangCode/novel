## 一、字数口径：从硬区间改为下限制（2026-09-29 裁决）

### 教训
硬上限（2800-3200）会把"为了不超标"异化成"为了达标而扭曲结构"。

### 实例
第19章初稿4452字，为压进3200做了**20+轮删减**。代价是制造了原稿不存在的结构损伤：
- 一次把场景结尾切到了 `---` 分隔符另一侧，上下文直接断裂，花两轮才修复
- 多处承接段被削薄，读者读得懂但感觉"少了什么"

### 裁决
改为 **不少于2400字、不设硬上限**；目标带2800-3200降为**建议值，非验收线**。

### 可执行动作
- **字数与内容完整性冲突时，内容完整性永远优先**
- 明令禁止四类"卡字数"操作：①删承接段致上下对不上 ②把场景切成两半落悬空位 ③删铺垫对白致后文反转失据 ④用心独白/重复信息注水凑数
- 历史章（第1-18章）不回溯返工，标注为"历史口径达成"

权威源 `设定/文风基准.md` §一.0｜锚点 `设定/已固化锚点清单.md`「单章字数口径」｜台账 `状态/行动清单执行台账.md` R3｜skill `SKILL.md` §7.3.1

## 二、第19章删减过头专项复盘（2026-09-29）

共发现 **6处损伤 = 2处硬伤 + 4处删减过头**。

### 硬伤1·数量指代自相矛盾
删减中留下「今天少了一个」，而结尾又认出**两个**人（黑布鞋+灰布鞋）。与第18章「那两个人昨天就散了」冲突——"少了一个"没有依据。

> **教训**：**数量指代跨场景互为约束**。"少了一个/两个/三趟/六两"这类计数句，删任一处必伤另一处。删减对话时必须同步核对本章内所有数量指代。

### 硬伤2·同一信息写两遍
「散了的狗第三天回头」在撂摊段与收尾段各出现一次，结尾又补「昨天跟了走三里」复述前文。

> **教训**：压字数时最易砍的是**回顾性复述**，但回顾句常承担转场功能——直接删会让段落失去引子。正确做法是**保留一句、删掉整段复述**。

### 删减过头3·章纲点名的机制被削平
章纲明确写「一百七十五块的算式算得出，但今天不收」，被压成无支撑的断言「我没有本钱收一百斤」。读者算不出这笔账（他一天卖56文却说收不起100斤），"主角克制"变成空转。

> **教训**：**章纲点名的机制/算式，即使只剩一句话也要保留**——它承担的是"主角克制"的说服力，不是凑数字的内容。已回补完整链条：175块→全部家当够收不到50斤→涨到六块多37.5→不够犯险→今天不收。

### 删减过头4·机制后文用到但前文没交代
「不识字只递不读」是死信箱的物理基础，原稿后文大段论述"不识字就拆不了"，前文却没写走线者不识字，读成悬空。

> **教训**：**凡后文依赖的机制，必须在前文场景落地。**

### 删减过头5·推理链断了一环
「你上来不问矿粉，不问灵芝，你问血芝」缺"他凭什么认定陈默是行商"的前置。

> **教训**：**推理类台词的每一环都是推理链的一节**，删中间一环，后面的结论就成了作者钦定。

### 删减过头6·读数位"主动选择"未写明
章纲要求「读数位：无（**主动选择**）」，正文完全没提。读者会以为作者忘了这场戏，而非刻意留白。

> **教训**：**章纲的"读数位：无"必须补一句主动选择的理由进正文**（"望气要抬手／今天他改数人"），否则留白被误读为遗忘。
> 效果：第18章望气 → 第19章数人 → 第20章誊数，三章读数策略形成递进。

### 落库位置
`设定/已固化锚点清单.md`「复盘教训登记（2026-09-29·第19章删减过头专项复盘）」

## 三、第20章产幻事故与修正（2026-09-29）

### 事故
原稿让蓝星侧列出了**七个点位的坐标数据**。但陈默在第11章（交割万法宗情报）、第19章（只写「四块半，北线断了」一行）**从未向蓝星报过界石三数与老井数**。

这正是 skill 反复警告的"**写到后面忘了前面**"——作者自己被前文带偏，产生了与设定库矛盾的幻觉内容。

### 修正
把信息闭环拧回来：
- 纸上**只有他报出的一个价**，加上**一个他自己都没写进去的时间**（他写那行字时没想到要写）
- 苏薇的追问因此变成「这个数你什么时候量的」（追他漏写的）→ 再要数据（「数据呢。」无落款无问号）
- 七个点与地名**只留在他自己的册子上**

### 铁律
> **蓝星侧掌握的本地数据，必须能在前文章节找到他投递过的对应物。**
> 写任何"后方知道了某本地情况"的戏之前，先问：**这条信息他什么时候、用什么渠道、投过什么内容？** 答不上来就是产幻。

### 附带修正的3处硬伤
| 问题 | 修正 |
|---|---|
| 年数误写"三年前" | 界石/老井/镇口一律**四年前**（对齐第14/18章） |
| 陈默视角出现「方舟基地的坐标记法」 | 删（蓝星内部知识，POV人物不可能知道） |
| 与第18章「十二年来头一回睡得很沉」撞车 | 改写，避免同一句式重复 |

### 落库位置
`设定/已固化锚点清单.md`「第20章同步锚点」第3条｜`状态/伏笔追踪表.md` F-002

## 四、生成失控：机检抓不到的一类故障（2026-09-29）

### 症状
第20章第一次生成**严重失控**：反复重放同一场景、人物名错乱、混入英文单词、段落间毫无衔接。

**它不报错、不中断，字数甚至达标**——字数/半角/禁词机检全部通过。**纯机检抓不到，肉眼才看得出。**

### 成因
单次生成试图覆盖过多内容（一章跨4天、6个场景），超出单次输出稳定承载。

### 预防动作
1. 一章最多拆 **3-4个场景**，按时间跳跃切分
2. 每次 `editor` 写入控制 **3000字以内**，超了分次写
3. **禁止一次生成跨越"日"**（第1天写完就停，另起一次写第4天）
4. 每场写完立即跑重复检测，别等全章写完

### 检测脚本
见 skill `SKILL.md` §7.3.2（重复段落检测 / 动作循环检测 / 单段臃肿检测）

### 落库位置
skill `SKILL.md` §7.3.2

## 五、工具层陷阱：insert_line 会挤断场景（2026-09-29）

### 现象
`insert_line` 插入位置选错，会把后续段落**挤到 `---` 分隔符另一侧**，造成"无引子的悬空段"。第19章出现过一次，浪费两轮修复。

### 纪律
> **每次插入后必须核对「段数 + 每段字数」，不能只看总字数。**
>
> ```python
> segs=s.split('\n---\n')
> print('段数',len(segs),'各段',[len(x.strip()) for x in segs])
> ```
> 总字数对但段数不对 = 结构已断。

### 落库位置
`设定/已固化锚点清单.md`「复盘教训登记」第6条｜skill `SKILL.md` §7.3.2

## 六、下限制的副作用：章节无限膨胀（2026-09-29 事后总结）

废除硬上限后，风险从"被字数绑架"转向"章节膨胀"——第20章5323字＝旧目标带1.7倍。

### 裁决
**开工前先分配分场预算**：一章4-6场，**每场 ≤ 总预算/场数**；单场超总章长30%即判臃肿。

### 关键区分
> **"不设上限"指的是不必为凑数字删承接段，不是允许注水。**
> - 删掉会破坏结构的是硬伤 → **不许删**
> - 重复同一动作/同一场景的是注水 → **该删**（第20章的"下楼→上楼→摊册子→看最后一页→看后巷灯"走了4遍，属此列，已清理）

### 落库位置
skill `SKILL.md` §7.3.3

## 八、数量账：规则空白导致的真实事故（2026-09-29）

### 提问触发
用户问：「规则里有没有记录**数字类**跨章计算错误的注意点？例如 1斤 → 消耗2两 → 还剩半斤」。

### 查证结论：**当时完全没有覆盖**
| 现有规则 | 管的什么 | 为何漏掉 |
|---|---|---|
| skill §7.2 第1条 | 数值与**设定库**是否冲突 | 1斤/2两/半斤全是新编的数，设定库里没有 → 不触发 |
| skill §7.4 模式1「消耗品复活」 | 物品**凭空复活** | 只查"已耗尽的又出现"，不查"剩下的量算不算得对" |
| skill §7.4 模式4「年数年龄漂移」 | **年龄账** | 那是年龄，不是数量 |
| 术语规范 §5.1 | **货币单位**换算（禁"块"入算） | 覆盖文/钱/两/灵石，不管**斤/两重量** |

**结论：跨章加减乘除是否守恒，是一类完全无人负责的错误。**

### 事故：用户提问后一扫描，第19-20章自己就埋了 5 处雷
| 原文 | 正确 | 错因 |
|---|---|---|
| 300斤涨到6块 = **175块** | **450块** | 把"涨额"和"总额"混了 |
| 50斤涨到6块 = **37.5块** | **75块** | 同上 |
| 56文是450块的**八百分之一** | **八分之一** | 除法错10倍 |
| 要撂**六百四十天** | **8天** | 沿用错误分母 |
| 第20章三天 = **168文** | **112文** | 56×3，但第三天是零 |

**最严重的后果**：后两处把主角"先立脚攒本钱"的克制理由**整个算反了**——按错账8天就能凑够钱，"攒本钱"的隐忍变成"作者不会算数"。

### 修正后的意外收获
改成正确算式后，"8天就够"这个**太漂亮的数字**反而给了更好的写法：
> 「八天里他得每天摆四个时辰的摊。可这八天里他得在这条街上待着不动。待着不动，那两个人就天天在他身后站着。」
> **「他不是攒不到这四百五十块。他是攒到了也带不走。」**

克制的理由从"钱不够"升级成"**处境不允许**"——比原写法有力得多。**算对了，戏才立得住。**

### 沉淀
1. skill 新增 **§7.3.4 数量账纪律**（含机检辅助脚本）
2. skill §7.4 失效模式表新增**模式6「数量账漂移」**
3. 新建 `状态/数量账登记表.md`——换算基准 + 活跃数量账 + **已作废错账留档**（防复发）
4. 术语规范 §5.1 补一条指向登记表

### 三句自检（写任何数字前）
1. **这个数在第几章出现过？** → 翻登记表核对守恒
2. **单位换过了吗？** → 斤↔两、文↔两↔块，不同轨不混算
3. **这次是收入还是支出？** → 方向别搞反（第19章"涨了就是175块"就是方向反了）

> **最要紧的一句**：本书斤/两双轨 + 文/两/块三轨，且主角是**全书最会算数的人**——他算错读者立刻会发现。**算术错误在本项目的人设下是加倍严重的失分。**

## 九、读者视角审校：四类逃过全部机检的盲区（2026-09-30）

### 触发
用户通读前5章后反馈「读不下去」，提出四条症状：①修仙界像武侠——修士对修士掏120两银子；②练气5层被3个凡人欺负不合理；③盐是固体，「跟着灵气走经脉」不物理；④内心戏太多、刻画刻意、流水账。**四条全部成立，且全部不在现有机检与审稿清单的覆盖范围内。**

### 共同病根：设定库自洽，执行层没有回查
| 症状 | 设定库本来就有 | 执行层干的事 |
|---|---|---|
| 120两银子 | `社会生活与经济`§一 三轨货币（铜银=凡人/灵石=修士/精盐=黑市） | 修士对修士场景写了凡人轨货币 |
| 凡人欺负练气5层 | 世界观§2.2 练气=洗筋伐骨；§6.2 凡人敬畏修士如神明 | 肉身碾压修士+杜撰一条查无出处的「滋事」宗规 |
| 盐杀物理 | `两界物理`§5.1 经脉=生物电-灵场伴生波 | 用「微末跟着灵气走经脉」盖过了现成科学模型 |
| 内心戏流水账 | 文风基准§二/三 Show don't tell、禁汇报式交代 | 执行成「内心tell」；叙事密度指标无人管 |

### 教训
> **现有机检全部在管「一致性」（字数/标点/数量账/道具状态/锚点对账），没有一条在管「可信性」与「可读性」。**货币-场景错配、行为-战力地位错配、卖点机制未过科学审、独白密度——四类问题机检全过、读者秒出戏。

### 新增审稿四查（并入批次复盘清单，与既有三项机检并列）
1. **货币轨检查**：双方均为修士的场景中，出现「两/文/贯」作为谈判筹码即报警（行商伪装戏须文本显式标明）
2. **战力地位检查**：任何「压迫/被欺/僵持」戏，先对双方修为与设定库的物理地位——凡人不得在肉身上压制修士；低阶被高阶压制须有非武力机制（规条/生计/靠山）
3. **卖点科学审**：章纲点名「名场面」的机制，成稿前必须在 `两界物理.md` 有登记条目或当场补登记——**没登记进设定的机制不许入文**（盐杀模型=§5.3，本批次补登）
4. **叙事密度量化**：每章对话占比≥25%（纯动作章可放宽但复盘说明）；连续无对白块≤500字；「看得分明/他知道/在心里过了一遍」类解说句式每章≤3处；禁止提前「解说道具精妙」（精妙只在兑现瞬间显现）；比喻预算每场≤1个新鲜喻
